# design-grammar: CI Workflows

*Part of the full [CI workflow inventory](../ci-workflows.md). This file covers design-grammar's CI situation; read the top-level doc first for the general validate/preview/publish pattern most projects follow, which this one does not.*

design-grammar has no workflow file of its own, and, corrected from an earlier version of this doc, it is **not** validated as part of `book-validate-dev.yml` either. Confirmed by grepping the full workflow directory rather than inferring from absence alone: the string "design-grammar" appears in `auto-label.yml` (label routing only) and once inside `book-validate-dev.yml`, but that single appearance is a stale comment documenting a one-off manual re-trigger on 2026-05-18 after an unrelated fix to `projects.json` (the contributor-crediting config, which happens to have a `design-grammar` project key), not a real path filter or validation step. A search across `book/**/*.py` for any reference to design-grammar's schema or content found nothing.

The only real check on this project's content is `npm run validate` (`design-grammar/scripts/validate.mjs`), and nothing in CI currently runs it. A malformed `grammar.yml` is only caught locally, when `build-html.mjs` fails here, or when StaffML's `sync-design-grammar.mjs` fails over in `interviews/staffml/`, see [`system_design.md`](system_design.md) for the full sync mechanism.
